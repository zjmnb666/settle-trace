# data/ · 数据说明

## 本仓库不含真实业务数据

所有演示用结算单、凭证、费用行、金额都是**代码生成的虚构样本**，
由 `src/app/agent_seed.py` 写入，可用 `python run.py seed --reset` 重建。

需求依据 `docs/requirements/discovery-report.md` 是访谈演练的整理稿，
其中的企业名称、角色、指标（`55 分钟/份`、`160 份/月`）均为合成基线，
**不代表任何真实企业的经营数据**。

## 演示数据里埋了什么

`JS-2026-0318` 这张单据是专门为测试设计的，8 行费用里放了 5 类问题：

| 位置 | 埋的问题 | 期望系统行为 |
|---|---|---|
| 第 1–4 行 | 正常 | 映射成功、证据齐全 |
| 第 5、6 行 | 跨币种疑似重复（USD / CNY，折算后差 2.6%） | 只提示、不删除，登记 duplicate |
| 第 7 行 | 无任何凭证 | 登记 missing_evidence，草稿列为缺项 |
| 第 8 行 | 「综合服务费包干」对不上服务项字典 | 低置信度 + `need_human` |
| 版本 | v1 已确认但被 v2 取代，v2 未确认 | 版本判定需「有效期 + 确认状态」双条件 |

## 如果要接入真实数据

1. 先脱敏：客户名、合同号、联系人、银行账号按规则替换；金额做保序扰动
2. 用 `python run.py ingest --corpus <文件>` 导入，支持 md / txt / 有文字层 PDF
3. 扫描件不做 OCR，会被拒绝（`E4009`）——识别错的字会变成凭空的金额，比读不了更糟

## 为什么这里没有 CSV/图片

评测结果在 `tests/eval/report.json`，流程图在 `docs/diagrams/`，
演示数据由 seed 脚本生成。这里只放说明，避免同一个文件在多处出现两个版本。
